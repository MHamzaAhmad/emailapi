# On Receive (Streaming)

The `onReceive` method provides a powerful, persistent connection to our event stream. Unlike webhooks, you don't need to expose a public URL or handle signature verification.

<Callout type="info">
  This is the recommended way to handle "reply-to-bot" flows, chat interfaces, or real-time dashboards.
</Callout>

## Usage

Pass a `cursor` to start listening. If you crash or restart, pass the last event ID you processed as the cursor to resume exactly where you left off.

```ts
import { createClient, EventType } from 'emailapi-sdk';

const client = createClient({ apiKey: 'em_...' });

// "0" means start from the beginning of time. 
// Empty string "" means start from now.
const cursor = ""; 

console.log("Listening for events...");

for await (const event of client.onReceive({ cursor })) {
  
  // 1. Handle Inbound Replies
  if (event.type === EventType.EMAIL_REPLIED) {
    const reply = event.payload.value;
    console.log(`User replied: ${reply.body}`);
  }

  // 2. Handle Delivery Status
  if (event.type === EventType.EMAIL_BOUNCED) {
    const bounce = event.payload.value;
    console.error(`Bounce for ${bounce.recipients.join(', ')}`);
  }
}
```

## Resiliency

The stream automatically handles keep-alives (heartbeats). If the connection drops, our SDK will throw an error, allowing your application logic to reconnect (with the last cursor).
